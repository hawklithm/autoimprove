## 2. Scene 三维模型

```
                    Scene (场景)
                         │
         ┌───────────────┼───────────────┐
         │               │               │
    Tech Stack      Functional       Business
    (技术栈)         Domain           Domain
                    (功能域)         (业务域)
         │               │               │
    ┌────┴────┐     ┌────┴────┐     ┌────┴────┐
    │         │     │         │     │         │
  react     node   auth      api   user-    billing
  vue       python database  ui    mgmt
  prisma    rust   testing   perf  analytics
  
  
  示例：一个具体的任务
  
  "修复 React 组件中的 JWT 认证逻辑"
  
         ↓
  
  Scene = {
    tech: ["react", "typescript"],
    functional: ["auth", "ui"],
    business: ["user-management"]
  }
```

## 5. 置信度计算

```
┌─────────────────────────────────────────────────────────────┐
│                    置信度计算公式                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Pattern 观察：                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 出现 5 次                                           │   │
│  │ 时间跨度：30 天                                     │   │
│  │ 显式修正：4 次                                      │   │
│  │ 测试通过：5 次                                      │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│         ↓                                                   │
│                                                             │
│  因素 1: 频率得分                                           │
│    5 / 10 = 0.5                                            │
│                                                             │
│  因素 2: 时间跨度得分                                       │
│    30 / 90 = 0.33                                          │
│                                                             │
│  因素 3: 用户行为得分                                       │
│    4 / 5 = 0.8                                             │
│                                                             │
│  因素 4: 验证结果得分                                       │
│    5 / 5 = 1.0                                             │
│                                                             │
│         ↓                                                   │
│                                                             │
│  加权平均：                                                 │
│    0.5 × 0.4 +    (频率权重 40%)                           │
│    0.33 × 0.2 +   (时间权重 20%)                           │
│    0.8 × 0.3 +    (行为权重 30%)                           │
│    1.0 × 0.1      (验证权重 10%)                           │
│    = 0.606                                                 │
│                                                             │
│         ↓                                                   │
│                                                             │
│  最终置信度：0.61                                           │
│                                                             │
│  判断：>= 0.6，可以生成规则（需要用户确认）                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 6. 规则生命周期

```
┌─────────────────────────────────────────────────────────────┐
│                    规则生命周期                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  创建 (Created)                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ • 从 Pattern 生成                                   │   │
│  │ • 用户手写                                          │   │
│  │ • confidence: 初始值                                │   │
│  │ • trigger_count: 0                                  │   │
│  └─────────────────────────────────────────────────────┘   │
│         │                                                   │
│         │ 用户确认                                          │
│         ↓                                                   │
│  激活 (Active)                                              │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ • 加载到会话上下文                                  │   │
│  │ • 影响 Claude 行为                                  │   │
│  │ • trigger_count++                                   │   │
│  │ • last_triggered_at 更新                            │   │
│  └─────────────────────────────────────────────────────┘   │
│         │                                                   │
│         │ 新的 Pattern 出现                                 │
│         ↓                                                   │
│  更新 (Updated)                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ • confidence 提高                                   │   │
│  │ • 内容修正                                          │   │
│  │ • 场景调整                                          │   │
│  │ • updated_at 更新                                   │   │
│  └─────────────────────────────────────────────────────┘   │
│         │                                                   │
│         │ 长期未触发                                        │
│         ↓                                                   │
│  衰减 (Decaying)                                            │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ • confidence 降低                                   │   │
│  │ • 提示用户："可能已过时"                            │   │
│  │ • 用户可以选择保留或删除                            │   │
│  └─────────────────────────────────────────────────────┘   │
│         │                                                   │
│         │ confidence < 0.3 或用户删除                       │
│         ↓                                                   │
│  归档/删除 (Archived/Deleted)                               │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ • 不再加载到上下文                                  │   │
│  │ • 归档的规则可以恢复                                │   │
│  │ • 删除的规则永久移除                                │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘


时间线示例：

Day 1    创建规则 (confidence: 0.75)
         ↓
Day 5    触发 3 次 (confidence: 0.75)
         ↓
Day 30   新 Pattern 强化 (confidence: 0.85)
         ↓
Day 60   触发 10 次 (confidence: 0.85)
         ↓
Day 150  未触发 90 天 (confidence: 0.85 → 0.72 衰减)
         ↓
Day 180  未触发 120 天 (confidence: 0.72 → 0.60 衰减)
         提示用户："这条规则可能已过时"
         ↓
Day 200  用户确认删除 → 归档
```

```
│   │   ├── rule-001 (元数据)

│   └── content/                     # 规则详细内容
│       ├── rule-001.md

│       │   ├── 原因说明
│       │   ├── 正例/反例
│       │   └── 相关会话
│       │

│       └── ...
│
├── sessions/                        # 会话存档
│   ├── 2026-05-30-abc.json
│   │   ├── 对话内容
│   │   ├── 工具调用

1. 加载 index.json (快速)

   ↓
3. 按需加载 content/*.md (详细内容)
```

## 总结

这个可视化展示了 AutoImprove 的核心概念：

1. **三维场景模型**：精确组织规则
2. **智能检测**：多信号融合，自动识别场景
3. **灵活规则处理**：遵守但不强制，用户优先
4. **动态演进**：规则随时间更新、衰减、归档
5. **高效存储**：索引+内容分离，快速查询

整个系统的设计哲学：
- **用户可控**：所有关键决策需要用户确认
- **智能但不强制**：提供建议，但尊重用户选择
